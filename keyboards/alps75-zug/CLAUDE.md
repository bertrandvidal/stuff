# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

alps75-zug: a 75 % keyboard (88 keys) rebuilt from an Apple Extended Keyboard II. It reuses the AEK's
Alps SKCM switches, caps and plate-mount stabilisers on a new KiCad PCB with a Raspberry Pi Pico (RP2040),
a laser-cut 1.2 mm plate and a 3D-printed sandwich case, and runs QMK/VIA firmware. The current revision
is **v0.3**. Everything is ordered from JLC (PCB + diode assembly, case, plate); `ORDERING.md` covers
the orders and the last-verified numbers. The firmware has not run on hardware yet.

Git root is `~/github/stuff`, a monorepo; this project is `keyboards/alps75-zug/`. Work on the
`alps75-zug` branch.

## How the pieces derive from each other

```
alps75-zug.kicad_sch + layout-internal-kle.json ──firmware/tools/extract_matrix.py──▶ keyboard.json, via/alps75-zug.json, keymaps
                                                  (check_definition.py proves they still agree)
alps75-zug.kicad_pcb ──fab/ground_pour.py (edits the board in place)──▶ GND pours + stitching vias
alps75-zug.kicad_pcb ──fab/export.sh──▶ fab/gerbers/*, alps75-zug-gerbers.zip, drill report/maps, drc.json
                                      └─ fab/jlc_assembly.py (+ .kicad_sch) ──▶ fab/alps75-zug-{bom,cpl}-jlc.csv
plate-88keys.jscad + alps75-zug.kicad_pcb ──case/tools/extract_refs.py──▶ case/src/lib/refs.py
      ──▶ lib/case_geom.py ──▶ case_top / case_bottom / plate / pcb / keycaps / assembly ──▶ STEP/, DXF/, STL/
```

Cross-cutting facts:

- **One shared frame for the case.** X/Y is the plate frame of `plate-88keys.jscad`: origin at the
  centre of the Esc switch (`"0,0"`), +X right, +Y towards the back (KiCad's Y is flipped). Z = 0 is the
  PCB's top surface. Every part is built in this frame, so `assembly.py` applies no transforms.
- **`extract_refs.py` parses the `.jscad` with regexes.** If you edit the plate, keep the existing
  line shapes (`const switch_N = … // "r,c" Wu`, `const hole…`/`customHole_N = translate([x, y, 0], circle(…))`,
  `const stab_N_a/b`), or update the parser. Never regenerate the plate from KLE-NG: the hand edits would be lost.
- **Matrix:** 6 rows × 17 cols; columns `GP0`–`GP16`, rows `GP17`–`GP22`; `COL2ROW`; USB VID `0xFEED`, PID `0x5A47`.
  The 17 F-row switches are rotated 90° (plate cutouts and footprints); the firmware layout is not rotated.
- **The GND net is unnamed** in the schematic: `Net-(U1-GND-Pad13)`.
- **JLC assembly:** only symbols with an `LCSC` field go into the BOM/CPL. Today that is the 88 diodes on B.Cu
  (1N4148WL, C108804); U1 and the switches are soldered by hand. A bottom-side part's CPL rotation is
  `180 − KiCad rotation`.

## Checking a change

Run these from the project root.

```sh
# Firmware ↔ schematic (under 1 s). Run after touching the schematic, the KLE layout, keyboard.json, the VIA JSON or a keymap.
python3 firmware/tools/check_definition.py          # exit 0 = pins, diode dir, 88 layout entries, VIA, keymaps all agree
qmk lint -kb alps75_zug -km zug --strict
qmk compile -kb alps75_zug -km zug                  # or -km default; build output stays in ~/qmk_firmware

# PCB DRC without rewriting fab/ (~2 s)
kicad-cli pcb drc --severity-error --severity-warning --schematic-parity --refill-zones \
  --format json --output /tmp/drc.json alps75-zug.kicad_pcb
python3 -c "import json,sys,collections as c;d=json.load(open(sys.argv[1]));print(dict(c.Counter(v['type'] for v in d['violations'])),'unconnected:',len(d['unconnected_items']),'parity:',len(d['schematic_parity']))" /tmp/drc.json
```

DRC baseline: 0 errors, 0 unconnected, 0 schematic-parity issues, plus **4 `silk_edge_clearance` warnings**.
Those 4 are known and accepted: U1's silkscreen outline runs 0.11 mm past the left board edge and gets clipped.
Anything beyond them is a regression.

For the case, render the output and look at it:
`~/.venvs/cadgen/bin/cadgen snapshot case/STEP/assembly.step out.png`
(`--mode section` gives a STEP cross-section; `--job file.json` runs a batch of render jobs).
`export_stl.py` prints each STL's bounding box. Compare it with the sizes recorded in `ORDERING.md`.

## Regenerating outputs

```sh
fab/export.sh            # everything in fab/: gerbers + zip, drill files/maps/report, drc.json, then jlc_assembly.py
```
`export.sh` regenerates every output in `fab/` (it doesn't touch the READMEs or scripts). Even when the board
hasn't changed, the gerbers and drill files come back with new creation-date lines, so don't commit that
date-only churn. `jlc_assembly.py` exits 1 if the schematic BOM and the board positions disagree.

```sh
KPY=/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3
$KPY fab/ground_pour.py              # after rerouting: replaces its previous pours + vias IN the .kicad_pcb; then rerun export.sh
$KPY case/tools/extract_refs.py      # after changing the plate .jscad or the PCB outline; rewrites case/src/lib/refs.py
```

Case, run from `case/`:
```sh
PY=~/.venvs/cadgen/bin/python
$PY src/assembly.py        # builds every @step model it uses → STEP/*.step (or run one model: $PY src/case_top.py)
$PY src/plate_drawing.py   # DXF/plate.dxf, the plate cut file (one CUT layer, mm, no kerf)
$PY src/export_stl.py      # STL/case_top.stl, case_bottom.stl, plate.stl
```
- `@step`/`@dxf` models go through cadgen's freshness gate. `export_stl.py` has none and always rebuilds.
  Rerun it after any change to `lib/case_geom.py`.
- The STLs must come from `export_stl.py` (build123d's exporter), **not** from a cadgen `@stl` model.
  cadgen's mesher leaves open edges in both shells, and print services reject non-watertight meshes.
- The "zug" engraving needs macOS's `/System/Library/Fonts/Supplemental/Arial Black.ttf` (`ENGRAVE_FONT`
  in `lib/case_geom.py`). It isn't in the repo because it can't be redistributed.

## Gotchas

- **KiCad may have the project open** (`~alps75-zug.kicad_*.lck` present). A GUI save overwrites any
  script edit to the `.kicad_pcb`/`.kicad_sch` (`ground_pour.py`, hand edits), so ask before editing those files in place.
- **The case has no BOOTSEL hole.** Every keymap must keep `QK_BOOT` (Fn + Esc) or Bootmagic (hold Esc
  while plugging in). Otherwise the case has to come apart to reflash.
- The VIA keymap is named `zug`, not `via`, because `qmk lint` rejects a keymap named `via`/`vial`.
  `VIA_ENABLE = yes` in `keymaps/zug/rules.mk` is what turns VIA on.
- The monorepo's root `.gitignore` ignores `lib`, and `case/.gitignore` re-includes `src/lib/`. A new `lib/` dir anywhere else needs the same treatment.
- Task numbers in the READMEs (1.4, 2.1, 3.1, 3.3) refer to a `tasks.md` that isn't in the repo.

## Keeping docs and versions in sync

- The board revision appears in: `(rev "…")` in the title block of both `.kicad_sch` and `.kicad_pcb`;
  the F.Silk legend `alps75-zug - v0.3 - 2026`; `fab/README.md`; `ORDERING.md` (the header and what changed);
  `firmware/keyboards/alps75_zug/readme.md` ("Hardware Supported"); and the `pics/` screenshot names.
- `fab/README.md`, `case/src/README.md` (the Z stack table) and `ORDERING.md` ("Before uploading") record
  verified numbers: board size, hole counts, DRC summary, STL and plate bounding boxes, engraving depth.
  Update them in the same change that makes them stale.

## Git conventions

- Commit directly on `alps75-zug`. No worktrees unless asked.
- One change per commit, in the imperative (e.g. `Deepen the "zug" engraving to 1.0 mm`).
- Regenerated outputs are committed too, usually as their own follow-up commit (`Regenerate the fab outputs for v0.3`).
